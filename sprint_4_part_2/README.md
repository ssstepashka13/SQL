# Gastro Hub Delivery — проект 4, часть 2

Светлана Степанова

Исследованы 15 исходных запросов. Пять самых медленных: №9, №8, №7, №2, №15. Структура и данные БД сохранены; новые индексы не создаются. Для №7 описано ограничение без индекса. Дополнительно ускорен №12.

- `report.md` — анализ, результаты и ограничения измерений.
- `project.sql` — итоговые запросы.
- `original.sql` — соответствующие исходные запросы; `workload.sql` — все 15.
- `plans_before.txt`, `plans_after.txt` — полные текстовые планы с фактическим временем и буферами.
- `statistics.json` — исходная статистика pg_stat_statements; `measurements.json` — замеры EXPLAIN ANALYZE.
- `diagnostics.sql` — команды повторной диагностики.
- `validation.sql` — автономные проверки эквивалентности на граничных данных; каждая должна вернуть mismatches = 0.
- `verification.txt` — результаты выполненных проверок.

Для воспроизведения восстановить отдельную БД из `project_4_part2.sql`, подключить pg_stat_statements и выполнить ANALYZE. Выполнить `workload.sql` в изолированном интервале сбора статистики, затем диагностику. Для выбранных исходных и итоговых запросов добавить `EXPLAIN (ANALYZE, BUFFERS)`. Номера запросов указаны комментариями. Приложенные планы получены в PostgreSQL 18.6 / PGlite 0.5.14; на сервере курса время и выбранные узлы могут отличаться.
